# Expection

## 基本流程

需要将当前的信息存放在 CSR(Control and Status Register). 

一旦发生 Expection, 就需要将触发 expection 的指令的后续指令进行清退, 因此, 一种比较简单的做法是直接在 WB 阶段进行 Expection 的处理.

同时 CSR 本身的写入, 也会和 GPR 一样, 在 WB 执行写入.

### 细节记录

#### 清空流水线

当 WB 发出 flush 之后, ID, EXE, MEM, WB 阶段都需要将其 `valid` 设置为 0. 这是在一个时钟周期内完成的.

> WB 阶段设置为 0 的原因是, MEM 的指令会在下一个时钟沿进入 WB, 因此, 需要设置为 0 拒绝进入.

`flush` 信号, 必须优先于 `allow_in` 进行处理.

#### 提前阻止访存

由于 store 类指令的访存发生在 EXE, 但是 flush 发生在 WB, 因此, 需要在 flush 类指令进入到 MEM 阶段的时候, 提前阻止 EXE 的访存.

同时, 如果 WB 里面是 flush, 也需要阻止访存, 从而:

```verilog
wire ex_redirect = ms_redirect | flush;
```

#### IF 不停顿

由于 flush 是在一个时钟周期内完成的, 现有的实现 IF 并不会停顿, 而是在一个时钟周期内, 写好 `next_pc`.

因此, IF 并不会停顿, 但是后面的 ID, EXE, MEM, WB 都需要等待上级灌入新的指令才重新开始.

#### 除法懒清空

除法正常情况下会占用 34 个周期, 但是 flush 只会清空 EXE 内部的除法状态机标记, 而不会停止除法运算, 同时需要注意的一点是, 由于新进入的除法会刷新除法器内部的状态, 因此并不会导致旧的除法结果被 flush 后进入的除法指令误读.

## 中断

中断和异常共享相同的路径, 但是由于其异步的特性, 因此, 其通常需要通过附着到一条指令上来完成.

具体而言, 外部设备通过拉高中断线, 发送中断, CPU 通过异步采样, 同步写入 CSR.Estat.IS 来发送中断信号.

CPU 在 ID 阶段检查 CSR 从而, 发出 `has_int` 表达有中断, 从而让中断自然的附着在流水线的 ID 阶段所处理的指令上.

## 同步异常

当前的指令执行的时候可能发生异常, 目前覆盖的同步异常如下:

- ADEF
  - 取值地址错误, 没有对齐
  - ecode=0x8, subcode=0x0
  - IF 检出
- ALE
  - 访存地址没有对齐
  - ecode=0x9, subcode=0x0
  - EXE 检出
- SYS
  - syscall 系统调用
  - ecode=0xb, subcode=0x0
  - ID 检出
- BRK
  - break 断点
  - ecode=0xc, subcode=0x0
  - ID 检出
- INE
  - 指令不存在
  - ecode=0xd, subcode=0x0
  - ID 检出

需要注意的是, 不同的同步异常的检出位置不一样.

## 已有的 CSR 

CSR 的编号来自指令里的 14 位立即数 `csr_addr`, 一共 16384 个位置, 而实际实现的只有下面这几个. 访问未定义或硬件未实现的 CSR 时, 读动作返回全 0, 写动作不修改任何软件可见的状态, 这是手册明确规定的行为.

之所以需要有这条规则, 是因为指令编码本身不区分已实现和未实现, 汇编器可以写出任何编号. 如果架构不给这种情况定义行为, 同一个二进制在不同实现上就会表现不同.

在 `CSR.v` 里对应 `case` 的 `default`:

```verilog
case (csr_addr)
    CSR_CRMD:   csr_rvalue = crmd_rvalue;
    default:    csr_rvalue = 32'b0;   // 读: 返回全 0
endcase

case (csr_addr)
    CSR_CRMD:   begin ... end
    default:    begin end             // 写: 什么也不做
endcase
```

> 以后实现新的 CSR 时, 需要把对应编号从 `default` 里移出来进入显式分支.

### CRMD

当前模式信息, 编号 0x0. 决定处理器核当前所处的特权等级, 全局中断使能和地址翻译模式.

- [1:0] PLV, RW
  - 当前特权等级, 合法值只有 0 和 3
  - 0 是最高特权等级, 即内核态; 3 是最低特权等级, 即用户态
  - 触发异常时硬件置 0, 确保陷入后处于最高特权等级
  - 执行 ertn 时硬件从 PRMD.PPLV 恢复到这一域
- [2] IE, RW
  - 当前全局中断使能, 高有效
  - 触发异常时硬件置 0, 确保陷入后屏蔽中断
  - 执行 ertn 时硬件从 PRMD.PIE 恢复到这一位
  - 异常处理程序若要重新开中断, 需要显式把这一位置 1
- [3] DA, RW
  - 直接地址翻译模式使能, 高有效
  - 触发 TLB 重填异常时硬件置 1
  - 执行 ertn 时, 若 ESTAT.Ecode 为 0x3f, 硬件置 0
  - 与 PG 的合法组合只有 (0, 1) 或 (1, 0), 配置成其它组合结果不确定
- [4] PG, RW
  - 映射地址翻译模式使能, 高有效
  - 触发 TLB 重填异常时硬件置 0
  - 执行 ertn 时, 若 ESTAT.Ecode 为 0x3f, 硬件置 1
- [6:5] DATF, RW
  - 直接地址翻译模式下取指操作的存储访问类型
  - 编码 0 为强序非缓存, 1 为一致可缓存, 2 和 3 保留
  - 软件把 PG 置为 1 时, 推荐同时把这一域置为 0b01
- [8:7] DATM, RW
  - 直接地址翻译模式下 load 和 store 操作的存储访问类型
  - 编码同 DATF
- [31:9] 保留, R0
  - 读返回 0, 且软件不允许改变其值

### PRMD

异常前模式信息, 编号 0x1. 触发异常时保存现场, 执行 ertn 时恢复.

- [1:0] PPLV, RW
  - 异常前的特权等级
  - 触发异常时硬件把 CRMD.PLV 的旧值记录到这一域
  - 执行 ertn 时硬件把这一域恢复到 CRMD.PLV
- [2] PIE, RW
  - 异常前的全局中断使能
  - 触发异常时硬件把 CRMD.IE 的旧值记录到这一位
  - 执行 ertn 时硬件把这一位恢复到 CRMD.IE
- [31:3] 保留, R0
  - 读返回 0, 且软件不允许改变其值

> CRMD 与 PRMD 是一对: 异常时 CRMD 存进 PRMD 然后被重置为内核态, ertn 时再从 PRMD 还原.

### ESTAT

异常状态, 编号 0x5. 记录异常的一二级编码, 以及各中断的状态.

- [1:0] IS[1:0], RW
  - 2 个软件中断的状态位, 位 0 对应 SWI0, 位 1 对应 SWI1
  - 这两个位的更新来源是软件, 写 1 置起中断, 写 0 清除中断
  - 这是整个 ESTAT 中唯一由软件写入的部分
- [9:2] IS[9:2], R
  - 8 个硬中断 HWI0 到 HWI7 的中断状态位, 高有效
  - 手册规定由硬件逐拍采样中断输入引脚
  - 软件写无效
  - 本实现所在的 CPU 与 SoC 接口没有中断输入引脚, 因此这 8 位恒为 0,
    对应的 ECFG.LIE[9:2] 也无效
- [10] 保留, R0
  - 读返回 0, 且软件不允许改变其值
- [11] IS[11], R
  - 定时器中断 TI 的中断状态位, 高有效
  - 核内倒计时定时器计数至全 0 时由硬件置起
  - 置起后保持, 直到软件清除
  - 清除方式: 向 TICLR 的 CLR 位(bit0)写 1, 且写掩码与写数据都必须为 1
  - TICLR 读出恒为 0, 写 ESTAT 本身无效
- [12] IS[12], R
  - 核间中断 IPI 的中断状态位, 高有效
  - 更新来源是硬件采样核外的中断控制器
  - **本实现不做核间中断**, 该位恒为 0, 对应的 ECFG.LIE[12] 无效
- [15:13] 保留, R0
  - 读返回 0, 且软件不允许改变其值
- [21:16] Ecode, R
  - 异常类型一级编码, 软件只读
  - 触发异常时硬件根据异常类型把对应数值写入这一域
  - 例如 0x0 是中断, 0x8 是地址错, 0x9 是地址非对齐, 0xb 是系统调用, 0xc 是断点, 0xd 是指令不存在
- [30:22] EsubCode, R
  - 异常类型二级编码, 软件只读, 共 9 位
  - 触发异常时硬件根据异常类型把对应数值写入这一域
  - 作用是在同一 Ecode 下继续细分, 例如 Ecode 为 0x8 时, 0 是 ADEF 取指地址错, 1 是 ADEM 访存指令地址错
- [31] 保留, R0
  - 读返回 0, 且软件不允许改变其值

estat.is 起到了类似于 Interrupt Table 的作用, 不同类型的中断对应 estat.lie 的不同的 bit.

### ERA

异常返回地址, 编号 0x6. 记录触发异常的指令的 PC.

- [31:0] PC, RW
  - 触发异常时硬件把触发异常的指令的 PC 记录到这一域
  - 执行 ertn 时硬件把这一域作为返回地址送到取指级
  - 记录的是异常指令自身的 PC, 不是 PC+4
  - ertn 不会自动加 4, 想在异常指令之后继续执行, 需要软件自己把这一域加 4
  - 是唯一既被硬件写又被软件写的地址类 CSR

### EENTRY

异常入口地址, 编号 0xc. 配置除 TLB 重填异常之外的所有异常和中断的入口地址.

- [5:0] 保留, R
  - 只读恒为 0, 写被忽略
  - 这决定了入口地址的低 6 位必须为 0, 即入口地址天然 64 字节对齐
- [31:6] VA, RW
  - 异常和中断入口地址的 [31:6] 位, 共 26 位
  - 所有普通异常和中断共用这一个入口, 只有 TLB 重填异常走 TLBRENTRY
  - 硬件不会按异常类型分散入口, 所以具体发生了什么, 需要软件在入口处读 ESTAT 的 Ecode 和 IS 来判断
  - 复位值为 0, 因此软件必须先配置这一域, 否则异常会跳到地址 0

### ECFG

异常配置, 编号 0x4. 控制各个中断的局部使能.

- [9:0] LIE[9:0], RW
  - 局部中断使能, 与 ESTAT.IS[9:0] 逐位一一对应
  - 只有该位为 1 时, 对应中断号才能参与中断判定
- [10] 保留, R0
  - 读返回 0, 且软件不允许改变其值
- [12:11] LIE[12:11], RW
  - 与 ESTAT.IS[12:11] 对应
- [31:13] 保留, R0  
  - 读返回 0, 且软件不允许改变其值

ecfg.lie 是 Expection 的使能表, 和 estat.is 相互对应, 用于控制对应的中断是否开启

### BADV

出错虚地址, 编号 0x7. 记录触发地址类异常的有效地址.

- [31:0] VAddr, RW
  - 触发地址类异常时, 硬件把出错的有效地址记录到这一域
  - 地址低位原样保留, 不做对齐处理
  - 取指地址错 ADEF 记录被取指的地址
  - 地址非对齐 ALE 记录访存指令的目标地址
  - 其他异常不覆盖这一域, 异常处理程序可以继续读到上一次的地址

### TID

定时器编号, 编号 0x40. 保存软件配置的定时器编号.

- [31:0] TID, RW
  - 软件可读写的定时器编号
  - rdcntid 指令读的就是这一域
  - 写 TID 不会装载或修改任何计数器

> 需要注意的, TID 通常用于软件区分其使用的是哪一个计时器, 但是由于当前课程实现的是单核 CPU, 只有一个 StableCounter, 因此, TID 本身只是为了 rdcntid 服务的.

### TCFG

定时器配置, 编号 0x41. 配置倒计时定时器的使能, 模式和初值.

- [0] En, RW
  - 定时器使能, 只有该位为 1 时才进行倒计时
  - 写入后若 En 为 1, 立即用新的 InitVal 重装计数器
- [1] Periodic, RW
  - 为 1 时到期自动重装, 为 0 时单次到期后停止
- [31:2] InitVal, RW
  - 倒计时初值, 实际装入的是 {InitVal, 2'b0}, 所以初值必须是 4 的倍数

关闭定时器时保留剩余计数值, 也不清除已经置起的到期标志. 单次到期后计数值停在 0xffffffff 这个停止值.

### TVAL

定时器数值, 编号 0x42. 读出倒计时定时器的当前计数值.

- [31:0] TimeVal, R
  - 定时器当前计数值, 软件只读
  - 定时器关闭或单次到期后读出 0xffffffff

### TICLR

定时中断清除, 编号 0x44. 清除 ESTAT.IS[11] 的定时器中断标志.

- [0] CLR, W1
  - 向该位写 1 清除定时器中断标志, 写 0 无效
  - 写掩码和写数据都必须为 1 才生效
- [31:1] 保留, R0
  - 读返回 0, 且软件不允许改变其值

读出恒为 0. 定时器处于使能状态且计数值已到 0 时, 到期优先于同一时钟沿的清除, 标志保持为 1.

### SAVE0 ~ SAVE3

数据保存, 编号 0x30 ~ 0x33. 给系统软件暂存数据用.

- [31:0] Data, RW
  - 仅供软件读写的数据
  - 除执行 CSR 指令外, 硬件不会修改该域的内容
  - 异常处理程序要保存现场时需要一个不破坏现场的暂存位置, 这几个寄存器提供了这个支点, 因为它们不属于通用寄存器
