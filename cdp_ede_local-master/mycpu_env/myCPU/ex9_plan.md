# Ex9 工作安排

在 Ex8 已通过的版本上继续开发, 两名组员分别在 `ex9_1`, `ex9_2` 工作, 最后由负责人合并到 `ex9`.

```text
共同的 Ex8 完成版本
    |-- ex9_1: 同步异常扩展
    |-- ex9_2: 计数器, 定时器, 中断
    `-- ex9:   合并与完整验证
```

两个分支必须从同一个确认过的提交创建, 开工时记录基线 commit. 各自完成译码, 数据通路, 控制信号, top 接线和测试, 不只交付未接入的模块.

## ex9_1

负责 `break`, INE, ADEF, ALE 和 BADV, 复用 Ex8 已有的 WB 上报与 flush 机制.

- break
  - 完成 ID 译码, 异常标志传递和 WB 上报
  - Ecode 为 0x0c, 不写通用寄存器, 不访存
- INE
  - 汇总所有合法指令, 未命中合法译码时标记异常
  - Ecode 为 0x0d
  - 检查现有译码是否过宽, 特别是 ertn
  - 与 ex9_2 提前确认计数器指令的合法编码, 合并时不能误判为 INE
- ADEF
  - 按指导书与 LA32R 手册实现取指地址错误检测
  - 异常标志必须和对应的 PC 配对传递
  - Ecode 为 0x08, EsubCode 为 0
  - 保存出错取指地址, 不能把它替换成发起跳转的指令 PC
- ALE
  - 在 EXE 根据访存宽度检测地址对齐
  - 字访问要求地址低 2 位为 0, 半字访问要求最低位为 0, 字节访问不产生非对齐异常
  - Ecode 为 0x09
  - 同拍禁止错误访存, 但指令仍需带着异常标志进入 WB
  - 错误 load 不能写回目的寄存器, 错误 store 不能修改内存
- BADV
  - 新增 CSR 和出错地址传递通路
  - ADEF 保存出错取指地址, ALE 保存出错访存地址
  - 地址低位原样保留, 不进行对齐处理
  - 其他异常不应无条件覆盖 BADV

本分支负责把以上异常完整接入流水线, 包括总线扩展, 异常码选择, ms_redirect 和副作用屏蔽. 可以修改相关流水级, CSR.v, mycpu_head.v 和 mycpu_top.v.

对应功能点为 n48, n50, n52 ~ n57. 需要验证对齐边界, 异常 PC, BADV, 错误指令不产生副作用, 并回归 Ex8.

## ex9_2

负责计数器指令, 定时器硬件, 软件中断和定时器中断的完整接入.

- 计数器指令
  - rdcntvl.w: Stable Counter 低 32 位写入 rd
  - rdcntvh.w: Stable Counter 高 32 位写入 rd
  - rdcntid: TID 写入 rj, rj 是目的寄存器而不是源操作数
  - 测试反汇编可能显示为 rdtimel.w / rdtimeh.w, 按 LA32R 的三种单目的形式实现
  - 不增加 Regfile 第二个写口
  - 完成译码, 结果采样, 目的寄存器选择, 写回和相关处理
- Stable Counter
  - 64 位自由运行计数器, 复位清零后持续递增
  - 不因流水线 stall 或 flush 停止, 也不因写 TID 或 TCFG 而清零
- 定时器 CSR
  - TID: 软件可读写的计数器编号, 不是计数值
  - TCFG: En, Periodic, InitVal
  - TVAL: 当前倒计时值, 软件只读
  - TICLR: 有效写掩码下向 bit0 写 1 清除定时中断, 读出为 0
- 倒计时定时器
  - 支持单次, 周期重装, 停止和重新配置
  - 到期置起定时中断请求, 请求保持到软件清除
  - 明确到期与清除同拍时的优先级
- 中断
  - 实现 ECFG.LIE, 软件中断状态和定时中断状态
  - 根据 CRMD.IE 和 ESTAT.IS & ECFG.LIE 判定是否有中断
  - 在确定的流水级把中断标志附着到有效指令上, 随指令传到 WB
  - Ecode 为 0, EsubCode 为 0
  - 被标记为中断的指令不得先访存, 写 GPR 或写 CSR
  - 处理前序 CSR 写与中断判定的相关, 以及 csrwr TID 后紧跟 rdcntid 的相关

Stable Counter 与 TCFG 控制的倒计时定时器是两个独立计数器, 不要合并成一份状态.

可以新增计时模块, 并修改 CSR.v, 相关流水级, mycpu_head.v 和 mycpu_top.v. 硬中断的外部接口由负责人统一确认, 不擅自改动平台顶层端口.

对应功能点为 n49, n51, n58. 需要验证 TID 读回, 计数器进位, 单次和周期中断, 中断清除, CSR 相关以及中断返回, 并回归 Ex8.

## 基本约定

- 新增或修改的逻辑使用 `// NOTE: ex9` 标注, 注释使用中文和英文标点
- 沿用现有 valid / allowin / ready_go 握手协议, 见 [Protocol](Protocol.md)
- 异常仍在 WB 上报, CSR 指令仍在 WB 访问, 不另建一套 flush 机制
- flush 优先于 allowin, 保留 Ex8 已有的取指重定向和除法处理
- 保留 ex_syscall, ex_ertn, csr_addr 的命名
- 新异常标志统一使用 ex_break, ex_ine, ex_adef, ex_ale, ex_int
- 总线字段在 mycpu_head.v 中记录位宽和含义, 打包与解包的顺序必须一致
- 两边各自更新分支内的总线布局, 合并时由负责人统一最终布局, 不凭另一分支的旧位号接线
- 不因测试反汇编出现某个名字就扩大实现范围, 以指导书和 LA32R 手册为准
- 不改官方测试镜像, golden trace 或比较逻辑来绕过错误
- 不做无关重构, 大规模改名或全工程格式化
- 各自在自己的分支提交, 不直接修改 ex9, 不重写公共基线历史

## 提交与验证

建议按功能拆分提交, 不把全部工作压成一个大提交.

```text
ex9_1:
    break + INE
    ADEF + BADV
    ALE + 副作用屏蔽
    定向测试

ex9_2:
    Stable Counter + TID + 三条读取指令
    定时器 CSR + 倒计时硬件
    软件中断与定时器中断接入
    定向测试
```

每个分支交付时说明新增端口, 总线字段, 检测或采样所在的流水级, 测试命令, 结果和未完成项. 至少执行 `make check`, 并回归 Ex8.

官方 Ex9 按顺序执行, 前面的测试失败会阻止后面的测试继续运行. 因此两个分支需要自己的定向测试, 不能把未跑到的测试视为通过. 如果使用裁剪后的测试程序, 单独保存并说明, 不覆盖官方用例.

计数器读数与中断响应涉及运行时机, 需要核对测试程序及 trace 比较的处理方式, 不能直接假定增加 stall 一定失败或一定无影响.

## 负责人合并

负责人负责两套功能的交叉部分, 而不是替两个分支补完各自的功能.

- 统一 mycpu_head.v 的总线布局, 核对各级打包, 解包与注释
- 合并 ID 的合法指令集合, 防止计数器指令被识别为 INE
- 按手册统一中断与各类异常的优先级, Ecode, EsubCode 和 BADV 更新条件必须对应同一个异常来源
- 合并 ms_redirect 和 EXE 访存屏蔽, 覆盖本级异常或中断, 更老的 MEM 异常以及 WB flush
- 检查 CSR 写与中断判定的相关处理是否因合并丢失
- 统一 top 接线, 确认硬中断接口与平台约束
- 补测中断与错误访存, CSR 写, 乘除法相邻的交叉情况
- 跑完整 Ex9 和历史回归, 再进行 Vivado 时序检查与上板验证
