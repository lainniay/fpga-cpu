# UART 模块

## 负责范围

实现 `cdp_ede_local-master/mycpu_env/soc_verify/soc_bram/rtl/UART/` 下的：

- `uart_tx.v`：串行发送。
- `uart_rx.v`：串行接收。
- `uart_mmio.v`：寄存器读写，并连接 TX/RX。

不修改 CPU 流水线、SoC 顶层、地址桥或板级约束。UART 基地址、总线接入、物理引脚和系统时钟适配统一在 merge 时处理；不替换原有 CONFREG 虚拟 UART。

## 公共约定

- 本文是本项目第一版接口约定，不是指导书要求采用的唯一实现方式。
- 当前端口名称、方向、位宽和时序约定固定；内部实现自行决定。修改接口前先协商，不修改其他负责人的文件。
- 独立验证只依赖本模块接口，不依赖其他尚未完成的模块；系统接线和整体验证在 merge 时完成。
- 所有模块使用同一输入时钟 `clk`，事件在上升沿采样；`reset` 是高有效同步复位，优先于收发和寄存器访问，取消未完成帧。
- 独立模块按 100 MHz 时钟约定验证。`baud_sel` 仅允许 0、1，调用方不得使用 2、3；帧中途改变选择不影响当前帧。

## 1. uart_tx

### 输入输出

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `baud_sel` | 输入 | 2 | 波特率选择，0 为 9600，1 为 115200 |
| `tx_start` | 输入 | 1 | 请求发送一个字节 |
| `tx_data` | 输入 | 8 | 待发送字节 |
| `tx_busy` | 输出 | 1 | 正在发送，不能接受新字节 |
| `uart_tx` | 输出 | 1 | 串行发送引脚 |

### 需要实现的功能

- 使用 8N1 格式：1 位起始位、8 位数据、无校验、1 位停止位；数据低位先发。
- 空闲及复位时串行输出为高电平，`tx_busy=0`。
- `tx_start && !tx_busy` 在上升沿成立时接受一个字节，锁存数据和本帧波特率；调用方每个字节提供一次一拍请求，不持续拉高等待忙结束。忙时忽略新的发送请求。
- 接受字节的沿后立即置 `tx_busy=1`，不能另留一个仍显示空闲的周期；不对 `tx_start` 做上升沿检测。
- 发送期间 `tx_busy=1`，完整停止位发送完毕后回到空闲。
- 当前分频常量 `10417/868` 按 100 MHz 时钟对应 9600/115200，实际系统时钟的适配留到 merge。

## 2. uart_rx

### 输入输出

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `baud_sel` | 输入 | 2 | 波特率选择，与 TX 一致 |
| `uart_rx` | 输入 | 1 | 异步串行接收引脚 |
| `rx_valid` | 输出 | 1 | 完整接收一个有效字节时的一拍脉冲 |
| `rx_data` | 输出 | 8 | 本次接收字节，在 `rx_valid=1` 时有效 |

### 需要实现的功能

- 对异步输入进行同步，按与 TX 相同的 8N1 格式接收。
- 检测并确认起始位，在数据位中心附近采样，低位先接收；一帧内使用固定波特率。
- 检查停止位，停止位错误的帧不产生有效字节。
- 完整接收后输出一次 `rx_valid` 脉冲，不能把一个字节重复上报。
- 复位回到等待起始位状态，并清除 `rx_valid`。

## 3. uart_mmio

### 输入输出

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `sel` | 输入 | 1 | 当前地址选中 UART |
| `we` | 输入 | 4 | 字节写使能，全 0 表示读访问 |
| `commit` | 输入 | 1 | 本拍完成一次有效寄存器访问，不是 CPU 的 WB 提交信号 |
| `wdata` | 输入 | 32 | 寄存器写数据 |
| `addr_off` | 输入 | 8 | 相对 UART 基地址的寄存器偏移 |
| `rdata` | 输出 | 32 | 寄存器读数据 |
| `uart_rx` | 输入 | 1 | 串行接收引脚，连接内部 RX |
| `uart_tx` | 输出 | 1 | 串行发送引脚，由内部 TX 驱动 |

### 寄存器

| 偏移 | 名称 | 行为 |
|---|---|---|
| `0x00` | STATUS | 只读；bit 0 为 TX_READY，bit 1 为 RX_VALID，其余位为 0 |
| `0x04` | TXDATA | 写低 8 位发送一个字节，要求 `we[0]=1`；读返回 0 |
| `0x08` | RXDATA | 低 8 位为待取接收字节，高 24 位为 0；有效读访问后清除 RX_VALID |

### 需要实现的功能

- 实例化 TX/RX，管理发送请求和接收数据暂存。
- 副作用只在时钟沿 `sel && commit` 成立时发生；不能仅因地址被选中就重复发送或清除接收状态。每个有效沿代表一次访问，连续两拍为 1 表示两次访问，不按 `commit` 上升沿计数。
- `addr_off` 为精确字节偏移，第一版仅支持表中 `0x00/0x04/0x08`，不支持其他字节地址别名。`we=0` 为读，`we!=0` 为写；只有 TXDATA 且 `we[0]=1` 的写访问有作用。STATUS 和 RXDATA 写入无副作用。
- `rdata` 采用组合读出，不依赖 `commit` 才产生。调用方在有效读取沿采样沿前的 `rdata`；RXDATA 读清除在该沿后生效。merge 时必须在这个沿保存读数据，不能清除 RX_VALID 后再去采样组合输出。
- `TX_READY = !tx_busy`。仅在 TX_READY 时接受 TXDATA 写入；忙时忽略写入，软件应先查询状态。本接口不支持等待握手。
- 每次有效 TXDATA 写入被接受的同一个沿，内部 TX 必须接受对应字节；沿后 TX_READY 变为 0。不能先接受 MMIO 写入，再延迟启动而留下仍显示可写的空窗。
- RX 的 `rx_valid` 脉冲到来时保存字节，保持 RX_VALID，直到软件有效读取 RXDATA。
- 第一版使用单字节接收缓冲：缓冲满且没有同时读取时丢弃新字节，保留旧字节；读取旧字节与新字节到达同拍时保存新字节，并继续置 RX_VALID。
- 缓冲原本为空，读取与新字节到达同拍时，本次读返回 0，新字节保留给下一次读取；接收完成以内部 `rx_valid` 被 MMIO 在上升沿采样为准。
- 无有效接收字节时读 RXDATA 返回 0；未选中或未定义地址读返回 0，未定义地址写入无副作用。
- 复位清空接收有效位，不产生发送脉冲。
- 当前 MMIO 没有波特率配置端口或寄存器，第一版内部固定 `baud_sel=1`（115200），TX/RX 本身保留波特率选择输入。
