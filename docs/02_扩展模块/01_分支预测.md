# 分支预测模块

## 负责范围

实现 `cdp_ede_local-master/mycpu_env/myCPU/branch_predictor.v`。

模块根据取指 PC 预测是否跳转及跳转目标，并根据 ID 提供的真实结果更新预测记录。只实现预测器内部逻辑，不修改 IF、ID、公共总线或顶层；系统集成在 merge 时处理。

## 公共约定

- 本文是本项目第一版接口约定，不是指导书要求采用的唯一实现方式。
- 当前端口名称、方向、位宽和时序约定固定；内部实现自行决定。修改接口前先协商，不修改其他负责人的文件。
- 独立验证只依赖本模块接口，不依赖其他尚未完成的模块；系统接线和整体验证在 merge 时完成。
- 所有时序事件以 `clk` 上升沿为准；高有效同步复位优先于正常更新，复位沿不接受更新。

## 输入输出

方向均相对于 `branch_predictor`。

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `clk` | 输入 | 1 | 时钟 |
| `reset` | 输入 | 1 | 高有效同步复位 |
| `query_pc` | 输入 | 32 | 当前查询的指令 PC |
| `pred_hit` | 输出 | 1 | 查询 PC 命中有效预测记录 |
| `pred_taken` | 输出 | 1 | 预测是否跳转；未命中时输出 0 |
| `pred_target` | 输出 | 32 | 预测跳转目标；未命中时输出 0 |
| `upd_valid` | 输入 | 1 | 本拍有一条有效分支结果需要更新 |
| `upd_pc` | 输入 | 32 | 被更新的分支指令 PC |
| `upd_taken` | 输入 | 1 | 该分支实际是否跳转 |
| `upd_target` | 输入 | 32 | 该分支的实际跳转目标，与本次是否跳转无关 |

例如：位于 `0x100` 的条件分支目标为 `0x200`，实际没有跳转，则更新输入为 `upd_pc=0x100`、`upd_taken=0`、`upd_target=0x200`，不是把目标更新成 `0x104`。

## 需要实现的功能

- 使用现有宏定义的 64 个表项，保存有效位、PC 标记、跳转目标和两位饱和计数器。
- PC 按 `index=PC[7:2]`、`tag=PC[31:8]` 查询；只有有效位和标记均匹配才命中。
- 查询为组合逻辑，不等待额外时钟，也没有查询握手。计数器 `00/01` 预测不跳，`10/11` 预测跳转。
- `upd_valid=1` 时在时钟沿更新一次：实际跳转使计数器饱和递增，实际不跳使其饱和递减，并维护目标和标记。新建或冲突替换条目时，应按本次实际方向初始化计数器，不能沿用旧 PC 的历史。
- 预测正确、预测错误以及实际不跳转的分支都可以收到更新，不能只更新预测错误的情况。
- 复位清除有效位，复位优先于更新。

## 查询与更新时序约定

- 查询没有有效信号，`query_pc` 可以持续保持或变化；不能把查询本身当作训练事件。
- 每个 `upd_valid=1` 的上升沿代表一次独立更新；连续两拍为 1 表示更新两次，不做边沿检测或自行去重。`upd_valid=0` 时忽略其余更新输入。
- 查询和更新同一个 PC 时，更新沿前查询旧记录，更新沿后查询更新后的记录；不要求、也不使用更新输入到查询输出的组合旁路。
- 调用方在采样沿保存当时的预测结果，不能用更新后的查询结果替代原预测。
- 复位沿清除有效记录；之后未命中的查询输出 `pred_hit=0`、`pred_taken=0`、`pred_target=0`。

预测器不计算真实分支条件，不判断当前预测是否错误，不清空流水线，也不决定异常重定向优先级。这些由 IF/ID 集成逻辑负责。
