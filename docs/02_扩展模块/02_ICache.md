# ICache 取指存储模块

## 负责范围

文件位于 `cdp_ede_local-master/mycpu_env/myCPU/`：

- `icache.v`：缓存查询、缺失填充、返回指令。
- `inst_mem_adapter.v`：将单字访存请求转换为同步 SRAM 读取。
- `inst_fetch_mem.v`：已有封装骨架，连接上述两个模块，不增加缓存算法或额外时序级。

只完成存储层内部逻辑，不修改 IF、ID、分支预测或公共总线；系统集成在 merge 时处理。

## 公共约定

- 本文是本项目第一版接口约定，不是指导书要求采用的唯一实现方式。
- 当前端口名称、方向、位宽和时序约定固定；内部实现自行决定。修改接口前先协商，不修改其他负责人的文件。
- 独立验证只依赖本模块接口，不依赖其他尚未完成的模块；系统接线和整体验证在 merge 时完成。
- 所有模块的 `clk` 为输入时钟，事件均在上升沿采样；`reset` 为高有效同步复位。地址均为 32 位字节地址。
- IF、ICache、adapter 使用同一时钟和同步复位。复位优先于握手，并取消所有未完成事务；复位后不得返回复位前的旧响应。

## 1. inst_fetch_mem 对外接口

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `req_valid` | 输入 | 1 | IF 提供有效取指请求 |
| `req_pc` | 输入 | 32 | 请求指令的 PC |
| `req_ready` | 输出 | 1 | 存储层可以接受请求 |
| `rsp_valid` | 输出 | 1 | 返回指令有效 |
| `rsp_pc` | 输出 | 32 | 对应请求的 PC |
| `rsp_inst` | 输出 | 32 | 返回指令 |
| `rsp_ready` | 输入 | 1 | IF 可以消费响应 |
| `inst_sram_en` | 输出 | 1 | SRAM 访问使能 |
| `inst_sram_we` | 输出 | 4 | 字节写使能，取指固定为 0 |
| `inst_sram_addr` | 输出 | 32 | SRAM 读取地址 |
| `inst_sram_wdata` | 输出 | 32 | 写数据，取指固定为 0 |
| `inst_sram_rdata` | 输入 | 32 | SRAM 返回数据 |

封装层只连接信号，保持子模块原有握手和读取时序。

## 2. icache 接口与职责

### 输入输出

`req_valid/req_pc/req_ready`、`rsp_valid/rsp_pc/rsp_inst/rsp_ready` 与封装层中的同名端口方向、含义一致。

额外的内部访存端口：

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `mem_req_valid` | 输出 | 1 | 发出一次单字读取请求 |
| `mem_req_addr` | 输出 | 32 | 读取字的地址 |
| `mem_req_ready` | 输入 | 1 | adapter 可以接受请求 |
| `mem_rsp_valid` | 输入 | 1 | adapter 返回一个有效字 |
| `mem_rsp_data` | 输入 | 32 | 返回的字 |

### 需要实现的功能

- 直接映射、64 行、每行 4 个 32 位字；`IC_LINE_WD=4` 表示每行字数。
- 地址划分：`tag[31:10]`、`index[9:4]`、行内字偏移 `[3:2]`、字节偏移 `[1:0]`。
- 命中时返回请求对应的指令和原始 PC。
- 未命中时，从 16 字节对齐的行首开始，以四次单字读取填满缓存行；未完成填充的行不能作为有效命中返回。
- 第一版采用阻塞式处理，最多保留一个未完成取指请求；不要求连续每拍接受新请求。
- 复位清除缓存有效位和未完成事务状态，复位期间不处理握手。

### 接口约定

- `req_valid && req_ready` 在时钟沿成立，才接受一次请求。连续多个沿握手表示多个请求，不按 valid 的上升沿计数。
- 除复位取消外，每个已接受请求恰好返回一次响应，`rsp_pc` 必须等于对应请求的 `req_pc`，不得自行丢弃或重复返回。
- 请求接受沿之后才能产生其响应，不在接受沿之前组合返回新请求的数据。当前响应的有效性和内容不得组合依赖新请求的地址或有效信号。
- 允许在消费旧响应的同一个沿接受新请求，但不强制支持；不支持时拉低 `req_ready`，IF 会保持新请求。该沿的响应仍属于旧请求，不能被新请求覆盖。
- 第一版指令存储内容在运行期间保持不变，不处理自修改代码、指令存储写入后的缓存一致性或缓存维护指令。
- 请求等待接受时，请求方保持 `req_valid` 和地址；接收后缓存自行保存请求信息。
- `rsp_valid && rsp_ready` 在时钟沿成立，才消费响应。等待消费时必须保持 `rsp_valid`、`rsp_pc`、`rsp_inst` 不变。
- 内存请求同样通过 `mem_req_valid && mem_req_ready` 接受；等待期间保持请求和地址。
- 内存响应没有 `ready`，因此每次发出读取后必须保证能够接收返回数据。第一版约定最多一个未完成的单字访存请求，逐字请求、逐字等待返回。
- `mem_rsp_valid` 每个有效周期代表一个返回字，在上升沿由 ICache 采样；除复位取消外，每次接受的单字请求恰好返回一次。请求接受沿之后才允许产生其响应。
- 对外响应不得依赖 `rsp_ready` 才产生，避免握手死锁。
- 非对齐取指由 IF 转成异常，不要求 ICache 处理异常。
- 当前没有取消接口。已发出的旧路径请求仍正常完成；是否丢弃响应由 IF 决定，不在缓存内实现分支纠错。

## 3. inst_mem_adapter 接口与职责

### 输入输出

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `mem_req_valid` | 输入 | 1 | ICache 提供有效读取请求 |
| `mem_req_addr` | 输入 | 32 | 读取地址 |
| `mem_req_ready` | 输出 | 1 | 可以接受请求 |
| `mem_rsp_valid` | 输出 | 1 | 返回数据有效，每次请求返回一次 |
| `mem_rsp_data` | 输出 | 32 | 读取结果 |

`inst_sram_*` 端口与封装层同名端口的方向、含义一致。

### 需要实现的功能

- 接受请求后保存地址并驱动 SRAM 读取，不重复发起同一请求。
- SRAM 在 `inst_sram_en=1` 的上升沿采样地址，按同步读时序更新 `inst_sram_rdata`；adapter 必须在数据实际有效后返回。当前宏 `IMA_RD_LATENCY=1` 表示 SRAM 读取延迟，不保证从请求握手到响应恰好只有一拍，不能在读取采样沿误用尚未更新的旧数据。
- 用 `mem_rsp_valid` 标明返回周期；无响应背压，每个请求只返回一次。
- 取指不写 SRAM，`inst_sram_we=0`、`inst_sram_wdata=0`。
- 复位清除未完成事务和响应有效状态。
